# Refleksi P05 — Event Handling (2410010279)

1. Jelaskan peran sumber event, object event, dan listener dengan contoh dari kode Anda.

Sumber event itu komponen tempat kejadiannya terjadi, object event itu "bungkusan" yang membawa informasi kejadian, dan listener itu yang menjalankan tanggapannya. Contohnya di PengamatEvent: tombol klikButton (yang tulisannya "Klik saya") jadi sumber event. Waktu tombolnya diklik, dia menghasilkan ActionEvent (object event), lalu ActionListener yang sudah didaftarkan lewat addActionListener menjalankan method klikButtonActionPerformed, yang isinya cuma memanggil catat("ActionEvent", "tombol diklik"). Jadi intinya komponen tidak menangani kejadiannya sendiri, tapi melimpahkan ke listener.

2. Mengapa KeyListener tidak dapat ditulis dengan lambda, dan bagaimana NetBeans mengatasinya saat Anda memilih event keyReleased?

Karena KeyListener punya tiga method (keyPressed, keyReleased, keyTyped), jadi dia bukan functional interface. Lambda cuma bisa dipakai untuk interface yang punya satu method abstract. NetBeans ngakalinnya pakai kelas adapter: KeyAdapter sudah menyediakan implementasi kosong untuk semua method KeyListener, jadi waktu saya milih event keyReleased, NetBeans cuma menulis method keyReleased-nya saja, sisanya ikut bawaan KeyAdapter.

3. Apa keuntungan memisahkan KonverterSuhu dari form KonversiSuhu?

Logika hitungnya (keFahrenheit, keKelvin, keReamur) jadi terpisah dari tampilan. Form KonversiSuhu cuma baca isian, manggil KonverterSuhu, terus nampilin hasilnya. Untungnya, rumus konversinya bisa dipakai ulang di tempat lain dan gampang diuji tanpa harus buka GUI. Kalau ada koreksi rumus, cukup diubah di satu tempat saja.

4. Mengapa aksi pada itemStateChanged perlu memeriksa ItemEvent.SELECTED?

Karena waktu pilihan di combo box diganti, itemStateChanged kepanggil dua kali: sekali untuk pilihan lama (DESELECTED) dan sekali untuk pilihan baru (SELECTED). Kalau tidak dicek, aksinya jalan dua kali. Di waktuComboItemStateChanged saya tambah if (evt.getStateChange() == ItemEvent.SELECTED) supaya catat() cuma kepanggil sekali, untuk pilihan yang baru.

5. Kapan Anda memakai event handler dari GUI Builder, lambda, atau method reference?

Event handler dari GUI Builder saya pakai untuk event yang memang mau kelihatan di file .form, misalnya tambahButtonActionPerformed, kurangButtonActionPerformed, dan bagiButtonActionPerformed di KalkulatorSederhana. Lambda saya pakai untuk aksi singkat yang cuma satu baris, kayak kaliButton.addActionListener(e -> hitung('x')). Method reference saya pakai kalau aksinya sudah ada sebagai method tersendiri, kayak hapusButton.addActionListener(this::hapus).
